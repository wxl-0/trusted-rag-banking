# 面向银行业监管制度与统计报表的可信 RAG 问答系统 — 设计文档

**项目**：第五届中国研究生金融科技创新大赛 · 南京银行赛题  
**日期**：2026-06-13  
**技术栈**：Python · LangChain/LlamaIndex · FastAPI · Qdrant · 商业 LLM API  
**优先级**：系统完整性（所有功能可运行，指标全面达标）

---

## 一、整体架构

系统分为 5 层，数据从解析层流向服务层：

```
┌─────────────────────────────────────────────────────────────┐
│  1. 解析层（Document Processing）                            │
│     Word/PDF → 章节/条款结构树                               │
│     Excel    → 带行列元数据的表格记录                         │
│     输出：结构化 Chunk + 元数据（doc_id, 文号, 机构, 日期...）│
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  2. 索引层（Index）                                          │
│     Qdrant Collection A：制度文本（条款/段落粒度）            │
│     Qdrant Collection B：统计表格（单元格/行粒度）            │
│     BM25 索引：关键词精确匹配（文号/指标名称）                │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  3. 检索层（Retrieval）                                      │
│     查询路由 → 制度问题 / 表格问题 / 跨类问题                 │
│     混合检索：BM25 + 向量 + 元数据过滤                        │
│     Reranker 重排序                                          │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  4. 生成层（Generation）                                     │
│     查询分解（多跳问题）→ 分步检索                            │
│     Prompt 组装（强制引用来源，禁止超出依据范围生成）          │
│     答案 + 证据引用（source_title / URL / 位置）              │
└────────────────────────┬────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────┐
│  5. 服务层（Service & Eval）                                 │
│     FastAPI REST API                                         │
│     评测模块（准确率/引用命中率/幻觉率自动评估）               │
└─────────────────────────────────────────────────────────────┘
```

**核心设计决策：**

- 制度文本与统计表格使用两个独立 Qdrant Collection，避免相互干扰
- 查询路由在检索前判断问题类型，决定走哪条索引或组合召回
- 生成层强制 Grounded Generation：答案只能来自检索证据，无依据则拒答

## 二、解析层详细设计

### 2.1 Word/PDF 解析链

**目标**：保留章节编号、条款层级、发文机关、文号、发布日期。

```
原始文件
  ↓
格式检测（.doc/.docx/.pdf）
  ↓
文本提取
  ├─ docx → python-docx（保留标题样式 Heading1/2/3）
  └─ pdf  → pymupdf（按字体大小推断标题层级）
  ↓
结构树构建（章 → 节 → 条 → 款）
  ↓
条款级分块（每个 Chunk = 一条或一组相关条款）
  ↓
元数据挂载
```

每个 Chunk 的数据结构：

```json
{
  "doc_id": "NFRA-2024-001",
  "chunk_id": "NFRA-2024-001#第三章#第十二条",
  "text": "...",
  "source_title": "商业银行资本管理办法",
  "issuer": "国家金融监督管理总局",
  "doc_no": "银监发〔2024〕X号",
  "publish_date": "2024-01-01",
  "section_path": ["第三章 资本充足率", "第十二条"],
  "chunk_type": "clause",
  "source_url": "https://...",
  "local_path": "data/NFRA-2024-001.pdf"
}
```

### 2.2 Excel 解析链

**目标**：每个表格行可被独立检索，保留表头语义和维度信息。

```
.xls/.xlsx
  ↓
Sheet 遍历（openpyxl）
  ↓
表头识别（首行/首列/多级表头合并）
  ↓
按行转换为语义记录（自然语言化）
  ↓
元数据挂载（报表名称、期间、指标名称、单位）
```

每行生成一条 Chunk：

```json
{
  "doc_id": "STAT-2024-Q3-001",
  "chunk_id": "STAT-2024-Q3-001#Sheet1#R15",
  "text": "2024年三季度末，不良贷款率为1.56%，较上季度下降0.03个百分点",
  "table_name": "G11《资产质量情况表》",
  "indicator": "不良贷款率",
  "period": "2024Q3",
  "unit": "%",
  "row_index": 15,
  "chunk_type": "table_row",
  "source_url": "...",
  "local_path": "data/STAT-2024-Q3-001.xlsx"
}
```

### 2.3 共同输出规范

所有解析结果写入 `data/chunks/`（JSONL 格式），同时更新 `manifest.json` 记录解析状态，支持增量入库和复现。

## 三、索引与检索层详细设计

### 3.1 索引结构

| 索引                     | 内容             | 检索强项               |
| ------------------------ | ---------------- | ---------------------- |
| `collection_regulations` | 条款/段落 Chunk  | 语义相似、制度理解     |
| `collection_tables`      | 表格行记录 Chunk | 指标查询、数值取数     |
| BM25（rank_bm25）        | 全部文本         | 文号精确匹配、指标名称 |

Embedding 模型：`text-embedding-3-small`（OpenAI）；本地备用：`bge-m3`

### 3.2 查询路由

```
用户问题
    ↓
查询分类器（LLM 单次调用）
    ├── 制度事实 / 条款阈值 / 流程要求  →  走 collection_regulations
    ├── 统计取数 / 指标口径            →  走 collection_tables
    ├── 跨类问题（场景判断/多跳）       →  两路同时召回
    └── 超出范围                       →  直接拒答
```

### 3.3 混合检索流程

```
查询文本
    ↓
① BM25 召回（Top-20）
② 向量召回（Top-20）
③ 元数据过滤（issuer / period / doc_no，可选）
    ↓
RRF 融合排序（Reciprocal Rank Fusion）
    ↓
Cross-Encoder Reranker 精排（bge-reranker-v2-m3，本地部署）
    ↓
Top-5 Chunks → 生成层
```

### 3.4 证据定位粒度

| 粒度       | 示例                                   |
| ---------- | -------------------------------------- |
| 条款级     | 《商业银行资本管理办法》第十二条第二款 |
| 段落级     | 第三章第二节第3段                      |
| 表格单元级 | G11表・2024Q3・不良贷款率・第15行      |

## 四、生成层详细设计

### 4.1 整体流程

问题复杂度由第 3.2 节查询路由结果决定：路由结果为"跨类问题"时走多跳路径，其余走单跳路径。

```
检索结果（Top-5 Chunks）
    ↓
问题复杂度判断（来自查询路由结果）
    ├── 单路问题（制度/表格）→ 直接组装 Prompt → LLM 生成
    └── 跨类问题（多跳）    → 查询分解 → 多轮检索 → 合并上下文 → LLM 生成
    ↓
答案后处理（结构化输出解析）
    ↓
返回：answer + evidence_list
```

### 4.2 Prompt 设计

系统采用强约束 Grounded Generation，LLM 不允许超出检索证据范围作答：

```
[系统提示]
你是银行业监管制度问答助手。请严格依据下方提供的监管文件原文回答问题。

规则：
1. 只能使用【参考资料】中的内容作答，禁止引入外部知识
2. 涉及金额、比例、日期、机构名称、文号必须原文引用，不得改写
3. 注意区分"应当/必须""可以""不得""原则上"等规范强度词
4. 若参考资料不足以回答问题，回复："依据现有资料无法确认，建议查阅[来源]"
5. 每条答案末尾附上证据来源

[参考资料]
{chunks}

[问题]
{question}

[输出格式]
{
  "answer": "...",
  "confidence": "high/medium/low",
  "evidence": [
    {"source_title": "...", "section": "...", "text": "...", "url": "..."}
  ],
  "refuse_reason": null
}
```

### 4.3 多跳查询分解

针对跨文件场景判断题：

```
原始问题："2024年三季度末不良贷款率是否超过监管红线？"
    ↓
分解为子问题：
  Q1: 监管规定不良贷款率的红线是多少？  → 走 collection_regulations
  Q2: 2024年三季度末不良贷款率是多少？  → 走 collection_tables
    ↓
分别检索，合并证据 → 统一生成最终答案
```

### 4.4 幻觉抑制机制

| 机制         | 实现方式                                             |
| ------------ | ---------------------------------------------------- |
| 无依据拒答   | Prompt 强制规则 + `refuse_reason` 字段               |
| 数字核验     | 答案中数字必须能在 evidence text 中原文找到          |
| 置信度标注   | `confidence` 字段，low 时提示用户核查原文            |
| 版本冲突检测 | 同一文号多版本时，优先取 `publish_date` 最新的 Chunk |

## 五、服务层与评测详细设计

### 5.1 FastAPI 接口

```
POST /api/ask       # 主问答接口
POST /api/ingest    # 文档入库（触发解析→索引流程）
GET  /api/health    # 服务健康检查
```

**主问答接口：**

```json
// 请求
{
  "question": "商业银行不良贷款率监管红线是多少？",
  "filters": {
    "issuer": "国家金融监督管理总局",
    "period": "2024Q3"
  }
}

// 响应
{
  "answer": "根据《商业银行风险分类办法》第X条...",
  "confidence": "high",
  "evidence": [
    {
      "source_title": "商业银行风险分类办法",
      "section": "第三章第十二条",
      "text": "原文片段...",
      "source_url": "https://...",
      "local_path": "data/..."
    }
  ],
  "refuse_reason": null,
  "latency_ms": 1240
}
```

### 5.2 评测模块

```
data/eval/
  ├── qa_seed.jsonl       # 42条种子问答 + 自建扩充题
  └── eval_report.json    # 评测结果输出
```

| 指标               | 目标值 | 计算方法                           |
| ------------------ | ------ | ---------------------------------- |
| 制度事实准确率     | ≥ 85%  | LLM-as-Judge 对比标准答案          |
| 表格取数准确率     | ≥ 80%  | 数字精确匹配                       |
| 证据引用命中率     | ≥ 90%  | evidence source_url 与标准答案匹配 |
| 关键字段错误率     | ≤ 5%   | 正则提取数字/日期/文号比对         |
| 拒答率（超范围题） | ≥ 80%  | `refuse_reason != null` 比例       |

见第六节（含前端模块的完整版本）。

## 七、量化指标对照

| 赛题要求              | 系统设计对应点                      |
| --------------------- | ----------------------------------- |
| 制度事实准确率 ≥ 85%  | Grounded Generation + Reranker 精排 |
| 表格取数准确率 ≥ 80%  | 独立 Table Collection + 行语义化    |
| 证据引用命中率 ≥ 90%  | 强制 evidence 字段 + 条款级定位     |
| 关键字段错误率 ≤ 5%   | Prompt 规则 + 数字核验机制          |
| 拒答率 ≥ 80%          | 查询路由拒答分支 + refuse_reason    |
| 支持 ≥ 200 份文件入库 | JSONL + 增量 ingest 脚本            |
| 支持 Word/PDF/Excel   | 三条独立解析链                      |
