# ADR-002：文档版本与 Qdrant/BM25 索引原子发布

- 状态：已采纳
- 日期：2026-08
- 关联 Issue：[#9](https://github.com/wxl-0/trusted-rag-banking/issues/9)、[#10](https://github.com/wxl-0/trusted-rag-banking/issues/10)、[#12](https://github.com/wxl-0/trusted-rag-banking/issues/12)

## 背景

一个知识文档版本进入问答前，需要依次产生：

1. 私有原文件；
2. 结构化版本 Chunk；
3. Qdrant 向量点；
4. BM25 关键词索引代际。

这些产物跨越 PostgreSQL、MinIO、Qdrant 和文件系统，无法使用一个跨组件 ACID 事务。如果处理中直接覆盖线上索引，任一步失败都会造成：

- 新旧版本混用；
- Qdrant 已更新但 BM25 仍旧；
- 更新期间文档暂时不可检索；
- 重试产生重复点或多个活动代际；
- 残留半成品绕过正常发布流程。

## 决策问题

如何在不要求外部组件支持分布式事务的情况下，保证一个新版本要么完整可见，要么完全不可见，并让旧版本在失败时继续服务？

## 候选方案

### 方案 A：原地覆盖所有产物

实现最简单，但会暴露部分更新，失败时难以恢复旧版本，也无法保证向量和关键词索引一致。

### 方案 B：更新期间停止该文档检索

可以避免混用，但牺牲知识可用性，并且仍需要解决失败后的恢复和外部残留。

### 方案 C：不可变候选产物 + PostgreSQL 发布指针

每次上传创建不可变 DocumentVersion，先生成候选产物；所有产物通过验证后，再由 PostgreSQL 事务同时选择当前文档版本和活动 BM25 代际。检索必须同时服从索引元数据和 PostgreSQL 当前版本集合。

## 决策

采用方案 C，并按以下阶段处理：

1. 上传受理创建 KnowledgeDocument、DocumentVersion 和 IngestionTask；
2. 原件保存为私有不可变对象；
3. Worker 生成版本范围内的 Chunk、Qdrant 点和候选 BM25 代际；
4. 分别验证原件、Chunk 数量、Qdrant 候选和 BM25 校验和；
5. 取得文档级短期 Redis 协调锁；
6. PostgreSQL 锁定文档和活动 BM25 指针，核对候选开始时观察到的旧状态；
7. 在同一数据库事务中更新当前 DocumentVersion、活动 BM25Generation 和任务终态；
8. 后端实例检测活动代际变化后原子加载新 BM25，并在加载完成前保留旧实例。

Redis 锁只减少并发冲突，数据库状态和事务才决定最终赢家。

## 可见性规则

- `queued`、`parsing`、`indexing` 和 `failed` 版本不可检索；
- Qdrant 即使残留候选点，也必须被 PostgreSQL 当前版本集合过滤；
- BM25 只有 `published_at` 有效且被活动指针选择的代际可用；
- 候选失败时旧版本和旧代际保持不变；
- 文档逻辑撤回后立即从当前可见集合排除。

## 结果

### 正向结果

- 更新期间旧版本持续提供问答；
- 新版本只在全部产物成功后一次性可见；
- 向量和关键词检索遵循同一业务版本；
- 失败、重复投递和 Worker 重启不会破坏旧版本；
- 并发候选只有一个能够成为当前版本。

### 代价

- 需要版本标识、候选清理和活动代际管理；
- 外部存储可能暂时保留不可见残留，需要可重试清理；
- 检索必须应用当前版本过滤，增加一次业务状态同步；
- BM25 不能简单覆盖单一文件，需要管理不可变代际。

## 失败处理

| 失败位置 | 业务结果 |
| --- | --- |
| 保存原件失败 | 不创建可用任务，返回安全错误 |
| Redis 排队失败 | 任务标记失败并清理本次原件 |
| 解析失败 | 任务失败，候选不发布 |
| Qdrant 或 BM25 失败 | 任务失败，旧版本保持活动 |
| 发布前状态已变化 | 当前候选视为陈旧并失败，不覆盖赢家 |
| 候选清理失败 | 旧版本继续服务；同一任务后续重试清理 |

## 不变量

1. 同一逻辑文档最多一个当前版本。
2. 一个活动 BM25 代际只能对应已经发布的版本状态。
3. 当前版本和活动代际在同一数据库发布事务中更新。
4. 外部候选存在不能绕过 PostgreSQL 可见性规则。
5. 失败候选不能使已发布旧版本不可用。

## 重新评估条件

- Qdrant 或关键词索引提供可验证的跨索引原子别名切换；
- 系统引入多区域发布，需要新的全局一致性协议；
- 版本数量和候选清理成本要求新的保留与压缩策略。
