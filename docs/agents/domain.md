# Domain Docs

工程 Skill 在理解和修改本仓库前，应按本文件读取领域文档并沿用项目术语。

## 开始工作前

- 读取仓库根目录的 `CONTEXT.md`。
- 读取 `docs/领域模型.md`，确认业务对象、生命周期和不可破坏的不变量。
- 如果 `docs/adr/` 存在，读取与当前工作范围相关的 ADR。
- 如果上述文件不存在，直接继续，不为缺失文件单独扩展当前任务。

## 文档结构

本仓库采用单上下文结构：

```text
/
├── CONTEXT.md
├── docs/领域模型.md
├── docs/adr/
└── src/
```

`CONTEXT.md` 记录当前实现状态、已确认产品与技术决策和尚未确认事项；`docs/领域模型.md` 记录业务对象、关系、生命周期、核心不变量和领域术语；`docs/adr/` 记录影响系统结构的重要架构决策。

## 使用领域术语

Issue 标题、规格、任务、测试和代码命名应使用 `CONTEXT.md` 中定义的术语，不使用其中明确列为应避免的近义词。

如果工作需要的概念尚未出现在词汇表中，应先判断是否误用了项目外术语；确有领域缺口时，再通过领域建模补充。

## ADR 冲突

如果计划或实现与现有 ADR 冲突，应明确指出冲突及理由，不得静默覆盖原决策。
